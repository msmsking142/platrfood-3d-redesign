# Delivery Failure Protection

- **Pure logic:** `helpers/riderSearchDecision` owns `decide`, `compensation`, and `withinRadius`. **Orchestration:** `helpers/deliveryProtection` owns `tick`, `sweep`, `refundFailedOrder`, `evaluateAreaPause`, `availability`, `logEvent`, `onRestaurantAccepted`, `onPreparing`, `onReady`, and `onRiderAssigned`.
- **Tasks:** `riderSearchTick` uses key `rs-{orderId}`. Legacy `autoCancelNoRiderOrder` tasks (`norider-*`) delegate to `tick`. Delete `noRiderAutoCancel`; drop legacy `merchant_comp_*` columns. Make task and sweep execution idempotent.
- **Search stages:** Initial radius → expanded radius after `expandAfterMin`, with an at-risk notification and optional capped incentive → priority when the order is `READY`. Priority deadline is `readyAt + readyWindowMin` (configure 5–10 minutes). If never ready, deadline is `restaurantAcceptedAt + maxMin`. On delivery-failure cancellation, set `cancelCode` to `PLATFORM_DELIVERY_FAILURE` and set `noRiderCancelledAt`.
- **Incentives:** Add the incentive to `orders.riderBonus` and `orders.riderPayout`; reduce `orders.contribution` by the same amount. Zipto pays it—never deduct it from restaurant or rider earnings.
- **Restaurant compensation:** One `restaurant_compensations` record per order (`order_id` unique), a positive `restaurant_adjustments` entry, and a `restaurant_payable` ledger entry keyed `order:{id}:restaurant_compensation`. Statuses: `approved`, `not_eligible`, `disputed`, `rejected`. Merchants dispute through `restaurant/action` → `dispute_compensation`; admins decide through `admin/delivery_protection_action_POST`. Revoke only before payout. Re-approval uses ledger key `order:{id}:restaurant_compensation:{adjId}`. `createWeeklyPayouts` must include compensation-only restaurants and adjustments created before its cutoff.
- **Timeline:** Write `order_delivery_events` with unique `event_key` values `${orderId}:${suffix}`; retries must not duplicate events.
- **Area pause:** Store the expiry in `service_areas.orders_paused_until`. `quote_POST` reports `serviceAvailable` and `unavailableReason`; `place_order_POST` rejects paused-area orders with HTTP 503. Automatically pause an area after the configured failure threshold within its lookback window.
- **Sweep fallbacks:** Run `sweep` before queries in `customer/orders_GET`, `restaurant/dashboard_GET`, `rider/dashboard_GET`, and `admin/delivery_reliability_GET`, covering delays caused by the 25-task limit.
- **Rider eligibility:** Filter both the available-order list and acceptance by `riderSearchRadiusM` against the rider’s `lastLat`/`lastLng`. Allow riders with null coordinates.
- **Admin UI:** Add the `delivery-reliability` section using `components/AdminDeliveryReliability`.
